# 踩坑记录

按主题整理，每条包含：现象、根因、解法/教训。

## 1. 构建环境

### 1.1 Gradle 代理
- 现象：Gradle 直连 maven.neoforged.net 21s 超时，依赖下载卡 0。
- 解法：`mod/gradle.properties` 写 `systemProp.https.proxyHost=127.0.0.1` / `proxyPort=7897`。
- 坑：给 `gradlew.bat` 传 `-Dhttps.proxyHost=...` 会被 PowerShell→cmd 拆成两个参数，Gradle 报 "Task '.proxyHost=127.0.0.1' not found"。**不要给 .bat 传 -D 参数**，用 gradle.properties 或 `GRADLE_OPTS`。

### 1.2 JDK 版本
- 构建：JDK 21（`C:\Users\Tsutsutsu\.jdks\jdk-21.0.12.1+1`）。
- 游戏启动：实例必须 **Java 25**（c2me-opencl 是 class file 69，JDK21 会 UnsupportedClassVersionError）。

## 2. Voxy 数据读取

### 2.1 RocksDB 列族与编码
- 列族：`world_sections`（体素）、`id_mappings`（方块/群系名称）。
- 值：ZSTD 帧（`ZstdInputStream` 读）。
- key 大端 8 字节：`(lvl<<60) | ((y&0xFF)<<52) | ((z&0xFFFFFF)<<28) | ((x&0xFFFFFF)<<4)`。
- **陷阱：y 字段是无符号字节**，负的 section y（0xFE/0xFF）排序在正 y 之后，不是按世界坐标顺序！合并时不要假设"先低后高"。
- 体素：`light(byte)<<56 | biome(9bit)<<47 | blockId(20bit)<<27`。
- id_mappings key 前缀：`0x40` = 方块状态，`0x80` = 群系（NBT 文本，mod 群系无命名空间，如 `:woodland`）。

### 2.2 群系显示错误排查
- 现象：地图群系与 F3 不符（如薰衣草田显示冰刺之地）。
- 排查方法：`CacheProbe` 直接读 `.vxm` 缓存里该像素的 biome 字段；`IdDump4` 读 id_mappings + 该列体素的 biome 字段。
- 结论：biome 映射本身正确（id 55=ice_spikes，id 60=lavender_field）；显示错多来自**缓存/合并阶段的旧数据**，或 pixelBlocks=2 时像素取相邻更高列的群系。
- **重启游戏后恢复正常** 的情况，优先怀疑"旧 jar 运行态 / 旧缓存"，先用 CacheProbe 验证缓存内容。

## 3. 高度合并算法（历史踩坑）

### 3.1 bug 现象与根因
- 现象：地图上某点高度显示 -37，实际地表 63（把地下洞穴顶当成地表）。
- 根因（world3, x=23, z=-89）：
  - level 0 该列**没有地表 section**（数据缺失，sy=1 顶部即地表但被"地下切片排除"误伤）；
  - level 1 同样被误伤；
  - 最细层级只剩地下 section，top=-37；
  - **层级优先**让 -37 覆盖了 level 2 的真实地表 63。
- 历史修复的副作用：
  - v28 加"地下切片排除"（`topY==31 && !topFluid → NO_TOP`）修复了沙滩误判，但**误伤了"地表正好在 section 顶部"的列**。
  - v26 用 max（跨层级最高）→ 精度差（粗层级 top 是区域最高，系统性偏高）。
  - 阈值 32 / `curTop<63` 都会误伤山区/峡谷。

### 3.2 最终规则（MapData.flushSection）
1. 层级优先：`curTop == NO_TOP || lvl < curLvl || (lvl == curLvl && top > curTop)`。
2. **同层级固体补全**：`lvl == curLvl && solidHere > curTop` → top = 固体顶（洞穴顶修复，数据驱动）。
3. **粗层级补全**：`lvl > curLvl && curTop < 0 && top > curTop + 32` → 用粗层级（细层级缺地表数据；32 = 一个 level-0 section 高度，y<0 = 地下）。
- 验证：示例列 -37 → 63；全图差值只有约 0.42% 像素变化，集中在探索中心的小斑点。

### 3.3 教训
- 改合并规则**必须升 CACHE_VERSION**，否则旧缓存继续显示旧高度。
- 用"差值图"（pre/fix 逐像素）验证修复范围，不要只看单点。

## 4. 颜色格式（踩坑 5 次以上）

- **`GuiGraphics.fill(x0,y0,x1,y1,color)` 用 ARGB**（0xAARRGGBB）。
- **`NativeImage.setPixelRGBA(x,y,color)` 用 ABGR**（0xAABBGGRR）。
- 例子：视距框写 `0xE000FFFF` 期望黄色，结果青色（ARGB 下 R=00,G=FF,B=FF）；正确黄色 = `0xE0FFFF00`。
- 群系边界 NativeImage `0xC0FFFF00` 在 ABGR 下是蓝色（正确）。
- **规则：GUI 画颜色想清楚是 ARGB 还是 ABGR 再写。**

## 5. 1-bit 群系边界 shader（未解决，已回退）

- 尝试用 GL_R8 单通道 mask（68MB）代替全分辨率 RGBA（273MB），fragment shader 采样着色。
- 第一次（直调 GL + Tesselator/BufferUploader 手绘）：**Sodium/Iris 环境直接崩溃，无 Java 日志/无 crash-report**（GL 驱动级）。
- 第二次（TextureManager 注册 MaskTexture + RenderType/MultiBufferSource）：不崩但**线不显示**（shader 采样/discard 问题）。
- 最终回退全分辨率 RGBA。
- **教训**：Sodium/Iris 环境下不要用 Tesselator/BufferUploader 手绘、少直调 GL；1-bit R8 纹理在 GUI 的兼容性差。

## 6. 纹理与内存

- `TextureManager.register` 会自动 close 旧纹理，无泄漏。
- 关闭地图释放纹理（`releaseTexturesOnClose`，默认开）可释放约 560MB 显存。
- 群系边界纹理全分辨率 **CPU 273MB + VRAM 273MB**；关闭后释放、重新打开会重新生成（约 0.5s + 273MB 分配）——这是有意的取舍。
- 渲染临时数组曾每次分配约 600MB（8 个 int[18.9M]）；已改为**阶段共享的 scratch 缓冲**（补洞→平滑→等高线→群系标签顺序复用），降到约 170MB。

## 7. 缓存

- 缓存文件：`voxymap-cache/<storage父目录hash>.vxm`，magic 0x56584D31，带 CACHE_VERSION。
- **已移除 storage mtime 比较**（Voxy 频繁重写 RocksDB，比较会让缓存永远失效）——代价是数据变化后缓存不自动更新，需**手动刷新地图**（强制重建）。
- 缓存写入时 mtime 字段写 0（保留格式兼容）。
- 旧存档/已删存档的缓存会留在目录里（不自动清理），每个几十 MB，不影响正确性（按 hash 区分）。
- 升 CACHE_VERSION 的时机：**任何影响 pixels 内容的改动**（合并规则、pixelBlocks、海平面逻辑等）。

## 8. 配置与语言

- `ModConfigSpec` 的 push/pop 必须严格平衡，否则启动崩溃：`Attempted to pop 1 elements when we only had: []`。加配置项后检查 push/pop 数量。
- NeoForge 配置界面**直接显示 comment 原文，不翻译**，所以 comment 写成"中文 / English"双语。
- 配置项名称用 `translation("voxymap.config.xxx")`，lang 里给中英翻译。
- 按键分类：`key.categories.voxymap` 显示为 "Voxy Map"；按键名 `key.voxymap.open` / `key.voxymap.center`。

## 9. 界面与交互

- **打开地图的位置**：曾有一段旧代码在地图已加载时把中心改成"地图中心"，导致"没有总对准玩家"。现在 init 里只做"对准玩家 + 配置缩放"，不再依赖 onClose 保存（onClose 可能不执行/被释放纹理异常打断）。
- 缩放保留曾依赖 onClose 保存，日志里没有记录 = onClose 没执行；现在改为每次打开都用配置的 defaultZoom（用户最终要求）。
- 群系标签两段字号：**GUI 缩放 ≥ 4 且 zoom < 1** 时 0.5x，其余默认 1.0x；连续缩放会让文字模糊。
- 关闭地图的 N 键可能因 KeyMapping 队列累积导致关闭后立即重开；clientTick 里必须**总是清空 openKey 队列**。

## 11. 已知限制 / 未解决

- 1-bit 群系边界 shader 在 Sodium/Iris 下崩溃（已回退全分辨率）。
- 群系按 path 反查注册表，多 mod 同名 path 时可能选错（低概率）。
- 缓存不随数据变化失效（手动刷新）。
- 配置注释固定双语，不随语言切换。
- 视距框/群系叠加/样式切换等 UI 状态是静态字段，跨存档保留。
